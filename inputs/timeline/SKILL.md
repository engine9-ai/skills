# Build engine9 timeline files

engine9 represents person-level activity as timeline entries, never events. This skill defines the two on-disk shapes—Timeline Raw and Timeline ID—and explains how to construct them with `@engine9/input-tools`. Use it when designing plugin or ingestion output that will eventually load into a timeline-style table.

## Quick reference

| Question | Timeline Raw | Timeline ID |
| --- | --- | --- |
| Has `person_id`? | No | Yes |
| Has final `id`? | Usually no | Yes |
| Immediately loadable? | No | Yes |
| Typical producer | Edge plugin, collector, early ETL | Resolver, downstream worker |
| Next step | Resolve person and assign ID | Load timeline and detail tables |

## Concepts

A timeline entry is one fact about one person at one point in time, such as an email send, open, click, transaction, or signup.

| Field | Meaning |
| --- | --- |
| `ts` | Entry timestamp |
| `entry_type_id` | Numeric type from `TIMELINE_ENTRY_TYPES` |
| `person_id` | Internal person identifier |
| `plugin_id` | Source plugin and UUID namespace |
| `id` | Deterministic UUID derived from entry identity |

Timeline Raw files preserve activity before canonical person resolution. Timeline ID files contain the resolved person and final deterministic ID required by downstream loaders.

## File format

### Timeline ID

Use Timeline ID when data is ready to load into `timeline`, join to plugin-specific detail tables, and deduplicate by UUID.

| Field | Requirement | Notes |
| --- | --- | --- |
| `id` | Required | Generated by `getTimelineEntryUUID` or supplied as stable `remote_entry_uuid` |
| `ts` | Required | String or number parseable as a `Date` |
| `person_id` | Required | Internal numeric person ID |
| `entry_type_id` | Required | Integer from `TIMELINE_ENTRY_TYPES` |
| `plugin_id` | Required while generating `id` | UUID namespace |
| `source_code_id` | Optional | Numeric source-code identifier |
| `email_domain` | Optional | Usually a lowercase domain derived from email |
| Detail columns | Optional | May be copied into plugin-specific detail tables |

The downstream `timeline` table normally stores `id` as a text UUID primary key, `ts` as milliseconds since epoch, integer `entry_type_id` and `person_id`, and optional fields such as `source_code_id` and `email_domain`.

### Timeline Raw

Use Timeline Raw when source activity lacks a canonical `person_id` but contains enough information for later resolution.

| Field | Requirement | Notes |
| --- | --- | --- |
| `person_id` | Forbidden | Its absence defines this shape |
| `ts` | Required or derivable | May begin as a source-specific timestamp |
| `entry_type` or `entry_type_id` | Required | String name or numeric type |
| Person identifier | Required | For example `remote_person_id`, email, or phone |
| `id` | Optional | Usually an external ID, not the final engine9 UUID |
| Source metadata | Optional | `account_id`, `plugin_id`, URL, user agent, IP address, and similar fields |

A typical raw row contains `ts`, `account_id`, `entry_type_id`, `email`, `email_domain`, `url`, and `user_agent`, but no `person_id`. Raw web activity, email activity, and external API logs commonly use this shape.

## Workflow

### Construct Timeline ID directly

1. Resolve stable `person_id` and `plugin_id`.
2. Resolve `entry_type_id` with `getEntryTypeId` when only `entry_type` exists.
3. Generate or normalize `id` with `getTimelineEntryUUID`.
4. Emit `id`, `ts`, `person_id`, and `entry_type_id`.
5. Preserve optional source and detail columns needed downstream.

### Convert Timeline Raw to Timeline ID

1. Map source activity to `ts`, `entry_type` or `entry_type_id`, and resolvable contact information.
2. Resolve or create the person outside `@engine9/input-tools`.
3. Attach the canonical `person_id`.
4. Resolve the numeric entry type when needed.
5. Call `getTimelineEntryUUID` with `ts`, `entry_type_id`, `plugin_id`, and `person_id`.
6. Write a Timeline ID file, such as Parquet or CSV, with the complete fields.

Plugins and edge collectors often emit Timeline Raw first. Downstream services or server workers then resolve people, generate IDs, persist Timeline ID files, and load timeline and detail tables.

## Rules

**Rule:** Call timeline records entries, never events.

**Rule:** Timeline ID rows must include `id`, `ts`, `person_id`, and `entry_type_id`.

**Rule:** Timeline Raw rows must not include `person_id`.

**Rule:** Include `plugin_id` when generating an ID because `getTimelineEntryUUID` uses it as the UUID namespace.

**Rule:** Prefer numeric `entry_type_id`. A string `entry_type` may remain for debugging, with conversion handled by `TIMELINE_ENTRY_TYPES`, `getEntryTypeId`, and `getEntryType`.

**Rule:** Use `@engine9/input-tools` helpers instead of hard-coding entry type IDs, UUID generation, or UUID validation.

## Examples

### Timeline Raw row

```javascript
{
  ts: "2026-01-15T12:00:00Z",
  entry_type: "EMAIL_OPEN",
  email: "person@example.org",
  email_domain: "example.org",
  plugin_id: "<plugin_uuid>",
  url: "https://example.org/",
}
```

This row has enough identity information for later resolution but intentionally has no `person_id`.

### Timeline ID row

```javascript
{
  id: "<timeline_entry_uuid>",
  ts: "2026-01-15T12:00:00Z",
  person_id: 12345,
  entry_type_id: 31,
  plugin_id: "<plugin_uuid>",
  email_domain: "example.org",
}
```

The exact numeric type must come from `TIMELINE_ENTRY_TYPES`, not from a hard-coded example.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Loader rejects a Timeline ID row | Confirm `id`, `ts`, `person_id`, and `entry_type_id` |
| UUID generation fails | Confirm parseable `ts`, valid entry type, `plugin_id`, and `person_id` |
| Duplicate activity does not deduplicate | Confirm stable source identity and deterministic UUID inputs |
| Raw data cannot resolve to a person | Preserve a usable email, phone, `remote_person_id`, or equivalent identifier |
| Entry type conversion fails | Use a value present in `TIMELINE_ENTRY_TYPES` |
| Existing UUID is rejected | Validate it with `uuidIsValid` |
